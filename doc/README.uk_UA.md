# KreaProducts для Dolibarr ERP/CRM

KreaProducts — це розширений модуль керування продуктами для [Dolibarr ERP/CRM](https://www.dolibarr.org). Він розширює модуль продуктів харчовою цінністю, алергенами, BOM/технічними листами, інвентаризацією та автоматизаціями витрат і складу — для закладів HoReCa і ритейлу, яким потрібні стабільність, трасованість і коректний _food cost_.

## Можливості

### Харчова цінність та алергени

- Таблиця харчової цінності з автоматичним розрахунком, валідацією та оновленням.
- Поширення поживних значень між батьківськими/дочірніми продуктами, включно з BOM (MRP) при активному режимі.
- Керування алергенами з поширенням за відсотком від загальної ваги та маркуванням слідів.
- Підтримка нехарчових продуктів (виключені з розрахунку).

### Структура продуктів і BOM

- Повне дерево продуктів (асоціації + BOM/MRP, коли активовано) з ієрархічною навігацією.
- Детальний перегляд складу продукту (компоненти, кількості та підпродукти) з підсумком **собівартості**.
- Чітка ідентифікація зв'язків між продуктами та технічними листами, включно з **вихідними упаковками** за потреби.
- Зворотний перегляд (_де використовується_): список наборів/технічних листів і меню, де позиція використовується як компонент, щоб оцінити вплив змін вартості, замін і нормалізації сировини.
- BOM розбирання з походженням і зв'язками, видимими в технічному листі.
- Автоматичний каскадний перерахунок витрат на основі компонентів/технічних листів.
- Підтримка вкладених BOM (рядки BOM, що посилаються на іншу BOM) з коректним перенесенням витрат, харчової цінності та алергенів.
- Multi-company: спільні BOM (entity=0) доступні в усіх сутностях, із пріоритетом для BOM поточної сутності, якщо вона існує.
- Розбирання керується для продукту через додаткове поле `kreap_dismantle`.

### Коректні дати складу та інвентаризації (дата рахунку та дата-значення)

За замовчуванням Dolibarr фіксує багато рухів **на дату внесення/валидації документа в системі** — що може не збігатися з операційною реальністю. У середовищах із частими закупівлями це створює відхилення та шум у аналізі складу.

KreaProducts вирішує це обмеження двома ключовими автоматизаціями:

- **Надходження на склад за датою рахунку (постачальники):** товари оприбутковуються із **датою рахунку/датою надходження**, а не датою внесення документа в Dolibarr. Це усуває розбіжності, коли рахунок вводиться через кілька днів.
- **Інвентаризація за датою-значення (ретроактивно):** коригування інвентаризації застосовується за **датою інвентаризації (датою-значення)**, а не датою підтвердження. Це дозволяє ввести інвентаризацію з ранішою датою (наприклад, тиждень тому) і зберегти узгодженість виправлень та звітів — чого стандартний модуль не гарантує.
- **Перерахунок за фізичною інвентаризацією:** перерахунок запасів використовує **пораховану кількість** (qty_stock) за наявності, а qty_view — лише як резерв, щоб уникнути відхилень при задніх датах.

### Розумне керування упаковками та собівартістю одиниці (автоматичне розбирання)

У HoReCa часто купують один і той самий товар у різних упаковках — але для _food cost_ важлива **реальна собівартість одиниці** (наприклад, EUR/л, EUR/кг, EUR/шт).

Типовий приклад: **олія**. Її купують у **каністрах 10 л, 5 л, 1 л** або **коробках 12x1 л**. Якщо такі упаковки потрапляють у систему як "різні продукти", швидко з'являються невідповідності у залишках і собівартості.

KreaProducts вирішує це за допомогою **модуля BOM Dolibarr (переліки матеріалів / техлист - FM)**:

- Налаштовується FM для упаковки (наприклад, _каністра 10 л_), визначається конверсія в одиничний продукт (наприклад, _10x 1 л_).
- Після цього кожна закупівля такої упаковки автоматично виконує **розбирання** на одиничний продукт **без участі користувача**.

Цей процес:

- створює відповідні **рухи складу**,
- зберігає **пропорційну собівартість** і трасованість (джерело -> призначення),
- і гарантує готовність одиничного продукту для рецептів, інвентаризації та розрахунків маржі.

### Автоматичне оновлення витрат і _food cost_ (каскад)

KreaProducts також автоматизує оновлення **собівартості** та **food cost** кінцевих продуктів на основі їхніх технічних листів (BOM/FM).

На практиці:

- якщо компонент (наприклад, **олія**) має оновлену закупівельну ціну,
- усі продукти, що використовують цей компонент (наприклад, **картопля фрі**), **автоматично перераховуються**,
- тож _food cost_ та маржа завжди відображають реальність без ручних коригувань.

Ця функція особливо важлива в операціях з великою кількістю рецептів та частими закупівлями, де навіть невеликі зміни витрат мають одразу відображатися в кінцевих продуктах.

### Продуктивність і списки

- Спрощений список продуктів із можливістю приховувати позиції.
- Симулятор цін (Метрики та Маржа) з тестовим markup.
- Список рухів складу по продукту з **загальним залишком**.

## Вимоги

- Dolibarr >= 19
- PHP >= 7.0
- Обов'язкові модулі: Продукти, Склад, Постачальники, BOM/MRP
- Опційно: Партії (productbatch)

## Встановлення

1. Скопіюйте модуль у `custom/kreaproducts`.
2. Активуйте в Налаштування -> Модулі/Додатки -> KreaProducts.
3. Налаштуйте параметри на сторінці конфігурації.
4. За потреби імпортуйте скрипти з `sql/`.

## Налаштування (основні константи)

| Константа | Опис |
| --- | --- |
| `KREAPRODUCTS_DEFAULT_WEIGHT_LABEL` | Клас одиниць для ваги. |
| `KREAPRODUCTS_NUTRITIONAL_TABLE_TAB` | Показувати таблицю харчової цінності на вкладці техлиста. |
| `KREAPRODUCTS_ENABLE_COPY_AVG_TO_PRODUCT` | Показувати вибір і кнопку для копіювання середніх значень на 100 г. |
| `KREAPRODUCTS_ENABLE_COPY_ALLERGENS_TO_PRODUCT` | Показувати вибір і кнопку для копіювання алергенів до іншого продукту. |
| `KREAPRODUCTS_AUTO_SYNCH_BUY_PRICE` | Автоматично поширювати собівартість (каскадний перерахунок). |
| `KREAPRODUCTS_ALLERGEN_FULL_THRESHOLD_PCT` | Відсоток загальної ваги для врахування алергенів як присутніх. |
| `KREAPRODUCTS_ALLERGEN_TRACE_THRESHOLD_PCT` | Відсоток загальної ваги для позначення алергенів як слідів. |
| `KREAPRODUCTS_STOCK_MOVEMENT_DATA` | Використовувати дату рахунку для рухів складу. |
| `KREAPRODUCTS_SUPPLIER_MOVE_TIME` | Час для рухів по рахунках постачальників. |
| `KREAPRODUCTS_INVENTORY_DEFAULT_TIME` | Час за замовчуванням при створенні інвентаризації. |
| `KREAPRODUCTS_INVENTORY_CATEGORY_ROOT` | Коренева категорія для вибору інвентаризації. |
| `KREAPRODUCTS_DISMANTLE_BOMTYPE` | Тип BOM для розбирання. |
| `KREAPRODUCTS_DISMANTLE_WAREHOUSE` | Склад для рухів розбирання. |
| `KREAPRODUCTS_SIM_ENABLE` | Увімкнути симулятор цін. |
| `KREAPRODUCTS_SIM_DEFAULT_MARKUP` | Стандартний markup симулятора. |
| `KREAPRODUCTS_REPLACE_PRODUCT_LIST` | Замінити стандартний список продуктів. |
| `KREAPRODUCTS_DEBUG_LOG` | Увімкнути відлагоджувальні логи KreaProducts. |

Примітка: пороги алергенів — це відсотки від загальної ваги рецепта кінцевого продукту.
